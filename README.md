# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在接口层改，页面组件不做业务判断：通用流转在 `local-service.ts`，
  摆渡车的派发、到站、维保收口在 `frontend/src/api/shuttle-service.ts`。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 摆渡车到站与里程口径

到站收尾（状态回待命 + 里程累加 + 回写里程台账）**只有一处实现**：
`frontend/src/api/shuttle-service.ts` 的 `finalizeArrival`。两个入口都调它——

- 入口一（车上）：摆渡车列表行内的「确认到站」；
- 入口二（后台）：列表勾选「执行中」车辆后点「批量确认到站」。

**幂等**：派发任务时给车辆生成「趟次」（车辆编号-日期-序号），到站明细按趟次落库。
同一趟无论从哪个入口、提交多少次，里程只累计一次；重复提交返回成功但明确提示不再累计，
持久化层 `appendArrivalRow` 还会按趟次再去一次重兜底。

**状态机**：`派发任务` 仅允许 待命 → 执行中；`确认到站` 仅允许 执行中 → 待命；
`申请维保` 仅允许 待命/充电中 → 维保中。维保中、充电中的车辆派新任务一律挡回，
越级流转在接口层拒绝并说明原因。

**里程只有一份**：所有里程读数以 `vehicle_mileage`（车辆里程台账，与业务数据同在
`airport-ground-ops:entries` 里）为唯一权威副本。摆渡车调度、特种车辆维保两个模块的
页面列表与 CSV 导出，读到的里程都在接口层从这张台账注水，台账只在 `finalizeArrival`
里累加。业务行上的「里程读数」字段只是台账建账前的底数缓存。

**不一致时以台账为准**，理由：

1. 台账只有统一到站收尾这一个写入口，且每趟有幂等键，可与到站明细逐笔对账、可审计；
2. 业务行上的里程字段可能被手工改动或停留在旧值（历史数据就是两处各写各的才出的问题）；
3. 读路径全部从台账注水，行字段与台账漂移时下一次读取自动纠正，不会越滚越大。

**到站明细导出**：摆渡车页面「导出到站明细」把全部到站记录按车辆编号分组打包成一份
CSV（逐车小计 + 末尾合计）。页面统计卡「到站里程合计」与导出文件的合计行调用同一个
`arrivalMileageTotal()`，两边必然一致。

**回归验证**：`cd frontend && npm run verify` 会用 tsc 编译后在 node 里跑
`verify/shuttle-verify.ts`，覆盖两个入口、幂等、状态机门禁、台账一致性与导出合计。
